3. Signal worth writing about today

Monorepo documentation is still assembled by hand, and the leading tool's own monorepo mode has open rough edges

2026 monorepo guidance is remarkably consistent on tooling (Turborepo/pnpm/npm workspaces) but thin on documentation: the recurring pattern in current writeups is "add a Storybook" or "add a separate Next.js/Docusaurus docs app," treating documentation as a bolt-on rather than something the workspace configuration already implies. Meanwhile TypeDoc's dedicated monorepo path (entryPointStrategy: "packages") has multiple open issues as of 2026 around cross-package reference resolution, per-package option duplication (root-level config isn't inherited by child conversions — each package needs its own packageOptions block), and no built-in way to exclude one package from the glob. This is a real, current pain point for exactly the audience jsdoc-scribe already has a documented, simpler path for.

This is a different angle from every prior post: it's a technical comparison/tutorial hybrid (not yet used in that exact combination), targets developers and platform engineers rather than leadership (last two posts were CTO/security-leadership-facing), and it uses a real, already-shipped jsdoc-scribe capability — the Architecture Insight page's monorepo/workspace detection plus the documented programmatic-API pattern for a combined multi-package site — that has been mentioned in the 2026-08-01 Architecture Insight walkthrough but never given its own dedicated deep-dive.
