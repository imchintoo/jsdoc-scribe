3. Signal worth writing about today

Documentation's primary reader has already flipped from human to machine — and most doc-generation pipelines aren't built for that reader

This is a genuinely new data point, not a restatement of the 2026-07-31 "context rot" post. That earlier piece was about accuracy over time — stale docs silently degrading an AI coding agent's suggestions. Today's signal is about audience composition: Mintlify's midyear report shows AI-agent requests overtaking human page loads on its hosted docs (66% in July, up from 15.2% in January), and GitBook independently measured agents at 51.8% of intentional doc reads by May. Claude Code and Cursor account for roughly 95% of that agent share. Separately, Context7 (Upstash) has become a default MCP server specifically to stop agents from hallucinating library APIs by serving version-pinned docs straight into the context window on request.

The angle that hasn't been used yet: most teams' documentation pipelines were built assuming a human clicking through a rendered site, not an agent consuming a Markdown/plaintext context blob mid-task. That's a packaging and delivery problem, distinct from staleness. jsdoc-scribe's relevant fact here isn't a new feature — it doesn't generate an llms.txt file or run an MCP server today — but its output is regenerated fresh from the AST on every run via the programmatic API, which is exactly the shape of source needed to feed either pattern without a second, hand-maintained "AI docs" copy that drifts independently of the human-facing site. Worth writing as a positioning/practical piece for engineering leadership deciding where to spend on doc tooling next, not a feature announcement.
